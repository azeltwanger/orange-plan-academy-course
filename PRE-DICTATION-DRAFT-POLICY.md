# Pre-dictation draft policy

A researched lesson is not automatically Austin's script.

## Live layers

- `scripts/` contains Austin dictation where it exists and a protected research script where it does not.
- `DICTATION-PREP-CORE.md` and `DICTATION-PREP-ADVANCED.md` are the human-reviewed surfaces Austin should speak from before he dictates a non-dictated lesson.
- `dictation-drafts/`, when generated, provides a per-file version of the same workflow with the full research prose collapsed at the bottom.
- `MASTER-COURSE.md`, `MASTER-ADVANCED.md`, `lesson-text/`, and the research register preserve the complete facts, calculations, qualifications, and student reference material.
- Walkthroughs remain DO / SEE / warning sheets and are narrated naturally in the current app.

## Before dictation

A usable prep draft should provide:

1. A plain opening Austin could naturally start from.
2. The order of the explanation.
3. The example, calculation, or factual qualification that cannot be lost.
4. The decision or number the learner should write down.
5. A clean handoff to the module walkthrough.

It should not manufacture a hook, slogan, payoff line, repeated negation reversal, or identical `Your decision / Put it in Orange Plan / You are done when` spoken structure.

## After dictation

Austin's recorded words become the authority. The editor may:

- clean transcription mistakes;
- remove accidental duplicate phrases caused by dictation;
- verify app behavior, law, and arithmetic;
- move click paths into the walkthrough;
- flag an unresolved planning judgment.

The editor may not:

- compress Austin's useful repetition merely to make the prose tighter;
- replace his planning philosophy with a generic industry default;
- present editor-shaped prose as verbatim Austin dictation;
- add a polished closing line that Austin did not say;
- silently change a factual correction into a new planning recommendation.
