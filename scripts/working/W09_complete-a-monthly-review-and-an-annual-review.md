#### Chapter 1 — Complete a quiet monthly review

**Show:** From 9.1's monthly route, open Home. Read material issues, source dates, Your Money and any meaningful Recent Activity. Open the relevant account's How this account updates. Check Cash Flow's Your Plan uses, Reserve and confirmed upcoming Life events. Finish a genuinely quiet fixture without inventing an action.

**Narration:**

Start on Home and read the dates behind the current balances. If an account needs attention, open that account and read what updates automatically and what still needs your input. A provider name alone doesn't tell you whether purchase history arrived.

Check the changes you expected this month. Confirm a contribution arrived and was invested as intended. Look at Cash Flow's spending source, the cash Reserve and the next confirmed life event.

Then read the saved Plan's status and date. Account prices can be current while the Plan still reflects an earlier calculation. Don't change assumptions just because a price moved.

If the records are current and there's no new decision, the monthly check is complete. Keep the next reminder and close the plan.

**Overlay:** Monthly: source dates / expected changes / cash needs / current result

**Verify:** A quiet outcome is supported by the actual fixture. No forced task, refresh request, repeated strategy change or universal runtime claim. No loan monitoring reduced to monthly cadence.

**Capture dependency:** Verify Home issue/source state, How this account updates, Cash Flow source period, Reserve and current Plan receipt. Do not invent Recent Activity or a manual Recalculate control.

#### Chapter 2 — Resolve one meaningful exception

**Show:** Use the existing contribution-left-in-cash example. Trace the actual account record through contextual Add or update and source evidence. If instruction was never executed, keep the provider action outside the app; if data is wrong, use the supported correction and authoritative receipt. Show uncertain and deferred status honestly.

**Narration:**

Open the account where the contribution should have arrived. Compare the contribution date and amount with the provider record. Then check whether the intended investment was purchased or the money is still cash.

If the purchase instruction wasn't completed, fix that instruction with the provider. Don't add a fictional purchase in Orange Plan. If the purchase did happen but the record is missing, use the account's supported update or activity-import path and review the result.

Read the receipt before adding another entry. Existing balances and imported activity may describe the same money. Don't count them twice.

Save the supported correction and check the affected total. If evidence is missing, record exactly what's needed and leave the issue open. Remind me later postpones the question; it doesn't resolve it.

**Overlay:** Expected contribution → provider evidence → actual purchase or cash → correct action

**Verify:** No balancing purchase, duplicate import, silent deletion or invented executed trade. Resolved, deferred and uncertain remain distinct. Plan updates only for modeled changes.

**Capture dependency:** Verify account-context actions, source coverage, history/balance reconciliation and receipt on the filming build. Outside provider instructions and actual execution need separate evidence.

#### Chapter 3 — Complete the annual system review

**Show:** From 9.1's annual route, open the previous dated plan and Annual Plan Refresh. On a first review with no previous version, date the current plan and start the record from it. Review six areas using canonical owners: spending/Reserve in Cash Flow and retirement strategy; Portfolio and allocation; Debt; Tax opportunities; Bitcoin access; family documents/beneficiaries/insurance. Use an actual debt-payoff fixture before redirecting a former payment.

**Narration:**

Open last year's dated plan if you have it. For a first annual review, date the current plan and use it as the starting record. Then work through the six annual areas. Start with spending and the Reserve. If you're retired, open the spending-review process and compare the next year's spending and refill together. If you're working, check whether the target and funding pace still fit.

Open Portfolio and allocation and review any changed purpose or timeframe. Then check debt statements, tax windows and approaching deadlines. In Protect, check custody changes, family contacts, beneficiaries, documents and insurance.

For a debt that ended, confirm the payoff first. The former payment doesn't automatically become an investment contribution. Check the current cash needs, choose the new destination and save the contribution choice through Saving and investing. Complete the provider instruction separately.

Record only adopted changes and the outside actions still needed. Keep existing choices when they continue to fit.

**Overlay:** Annual: spending/Reserve / allocation / debt / tax / custody / family/insurance

**Verify:** Actual spending policy, input dates and comparison scope preserved. No automatic rebalance, presumed beneficiary sufficiency, destructive annual wallet test or prematurely available payoff money.

**Capture dependency:** Verify each owner route, Current/Preview spending and contribution flows, actual payoff milestone and supported annual review. Current thresholds and policy terms remain specifically verified, not supplied by the manuscript.

#### Chapter 4 — Handle a real change and a proposed response separately

**Show:** From 9.1's immediate-change route, use a labeled fictional income change. Save the fact in Cash Flow → Income at its supported effective timing. Inspect required spending/debt/Reserve, then compare a contribution response in Saving and investing. Reconcile any old future event already reflected in current facts.

**Narration:**

This example starts with an income change that has happened. Open Income in Cash Flow and update the actual source and timing. Keep the other facts unchanged so you can see what the income change does.

Read the bills, required debt payments and Reserve against the new cash flow. Then open Saving and investing to compare an affordable contribution response. The income change is a fact; the contribution amount is a choice. Review Current and Preview before saving the choice you intend to follow.

If the change was already listed as a future event, reconcile that event so the projection doesn't apply it again. Wait for the saved result to include the change before interpreting it.

A possible career break stays in Scenarios. An unexplained number needs a source correction or a focused support question, not several compensating edits to recover an old percentage.

**Overlay:** Changed fact → cash needs → proposed response → explicit save

**Verify:** Correct owner and timing; no duplicate event, invented calculation, compensating return override or unadopted preview in Current. Immediate obligations continue while an app issue is investigated.

**Capture dependency:** Verify Income timing, event lifecycle, Saving and investing Current/Preview, save/update receipts and result freshness. If unsupported, identify the blocked scene rather than claim it completed.

#### Chapter 5 — Keep the next review usable

**Show:** Save a dated summary/action record through actual supported views. Open Profile → Data & privacy → Export to inspect available export scope. Keep any sensitive backup separately; restoration is independently verified in a disposable authorized environment, never demonstrated by restoring over the current household plan. Create actual monthly/annual reminders externally if no app scheduler exists.

**Narration:**

Save the date, changes you adopted and the reason for each one. Give any remaining outside action a responsible person and due date. Keep future actions tied to the event that makes them possible.

Open the export options and read what the file contains before saving or sharing it. A readable summary and a restoration backup serve different purposes. If the export is a supported restoration backup, keep it protected and record its actual restoration status separately. If it's only a report or data export, keep that scope clear; it doesn't establish that the plan can be restored.

Put the monthly check and annual review on your calendar. Include separate triggers for loan thresholds, tax deadlines and important life changes. A note saying to create a reminder isn't the reminder itself.

At the next review, start with this dated record and update what changed.

**Overlay:** Dated decisions / actual action status / next reminder / separate protected backup

**Verify:** Actual save/reopen and export scope; no calendar event inferred from a note, assumed restore capability or sensitive file shared. Superseded instructions remain dated rather than current.

**Capture dependency:** Verify Profile export labels/formats/privacy and report save path. Restore is not promised by the future contract; any restoration test requires actual supported safe capability and separate evidence.

### Readback and finish

The member has a monthly facts check, an annual review of standing choices and a separate immediate-change route. Adopted changes belong to the current Plan; unresolved records and provider actions remain visible. A dated starting record and actual reminders support the next review. A quiet month may end with no change.
