7.2 Set up a hardware wallet and prove the backup works

============================================================

So in this lesson we're going to set up a hardware wallet and prove that the household can recover it before a meaningful balance depends on the backup.

The exact screens and backup format depend on the device. Follow the current instructions from the manufacturer for the exact model you own.

The planning standard is stable: the device is verified, the wallet is generated by the device, the backup stays offline, receive and send details are confirmed on the trusted device display, and recovery is tested under calm conditions.

== WHAT THE DEVICE AND BACKUP DO ==

The hardware wallet holds or uses the private keys needed to sign a transaction without exposing those keys to the connected computer or phone under the device's intended design.

The wallet backup is what allows the keys to be recreated when the device is lost, damaged, reset, or replaced.

The device can be replaced. The backup and any passphrase associated with that wallet cannot be guessed or recovered by the manufacturer.

Different wallets use different backup standards and word counts. Do not assume a backup works on every other device or software. Confirm compatibility before a real recovery or migration.

== BUY AND VERIFY THE DEVICE ==

Buy from the manufacturer or a verified authorized seller when the manufacturer supports one.

Inspect the package and follow the device's authenticity or firmware-verification process.

A new device should not arrive with a prewritten backup, an already-created wallet, or instructions telling you to use words someone else supplied.

If anything about the device, packaging, firmware, or setup process does not match the official instructions, stop and contact the manufacturer through a channel you find independently.

Do not use the phone number, QR code, or link inside an unsolicited message telling you there is a security problem.

== GENERATE A NEW WALLET AND BACKUP ==

Use the manufacturer's official app or supported setup process.

Generate a new wallet on the device. Record the wallet backup exactly as the device instructs and keep it offline.

Do not photograph it. Do not type it into a computer, phone, password manager, cloud note, website, support chat, or AI tool.

If the device uses a recovery process where words are entered, follow the manufacturer's supported method and make sure the sensitive entry occurs only in the way the device documentation says is safe.

Set the device PIN or other local access control. The PIN protects use of that physical device. It is not a replacement for the wallet backup.

If a passphrase is used, understand that the exact passphrase can create a separate wallet and may be required in addition to the backup. A forgotten or mistyped passphrase can lead to a different empty wallet. Passphrases belong in the advanced custody decision unless the household fully understands and has tested the process.

== VERIFY THE RECEIVING ADDRESS ON THE DEVICE ==

Before sending a meaningful amount, generate a receiving address and display it on the hardware wallet's trusted screen.

Compare the address shown by the device with the address in the sending app.

The connected computer or phone can display a changed address because of malware or a bad application. The device display is there so you can confirm what the hardware wallet actually generated or is about to sign.

Check the full address using the method supported by the device. Do not rely only on the first and last few characters copied from transaction history, because address-poisoning and clipboard attacks are designed around that shortcut.

Send a small amount that is meaningful enough to test the process and small enough that a setup mistake is survivable.

Wait for it to arrive and confirm the balance and transaction independently.

== TEST A SEND AS WELL AS A RECEIVE ==

A complete operating test includes sending a small amount back out.

Create the transaction in the wallet software, then verify the destination address, amount, and fee shown on the hardware-wallet screen before approving it.

The trusted display tells you what the device is actually signing. If it does not match the transaction you intended, reject it.

Do not approve a transaction because a support agent, email, direct message, or phone caller says it is required to secure the wallet.

== PROVE THE BACKUP WITHOUT CREATING A NEW RISK ==

There are several safe ways to test recovery, and the correct one depends on the device.

Some manufacturers provide a backup-check feature that verifies the recorded backup on the device without moving the funds.

A household may restore the backup to a compatible spare device or use another manufacturer-supported recovery drill.

A full wipe-and-restore can be a strong test, but do not wipe the only working device holding a meaningful balance unless the backup has already been checked, the exact recovery process is understood, and the household has a safe fallback. Use a small test wallet or spare device when that makes the test safer.

The test is complete only when the recovered wallet produces the expected accounts and addresses. Seeing an app open is not enough.

If a passphrase is part of the setup, test the exact backup-plus-passphrase combination. The backup alone may restore a different wallet.

== STORE BACKUPS AGAINST THE REAL RISKS ==

The backup has to survive the events the device does not.

A device and backup in the same desk can be lost to the same fire, flood, theft, or move.

Separate the failure domains. The appropriate locations depend on the household, legal access, privacy, and what other components are needed to move the Bitcoin.

Paper can be a valid temporary or low-stakes backup, but it can be damaged by water, fire, fading, or handling. A durable metal backup can reduce some physical risks, but it does not solve theft, discovery, or family access by itself.

Do not store every component of a multi-key or split-access system together simply because each one is individually protected.

== SOFTWARE AND FIRMWARE ==

Use the manufacturer's official application and verify the source before installing software or firmware.

Security updates can matter, but urgency is also used in phishing.

Before an update, confirm that the wallet backup and recovery process are current. Read the official release and instructions through a channel you access independently.

Do not enter the wallet backup into a computer because an update screen asks for it. A legitimate support person should not ask you to send or type the backup to them.

== BUILD A FAMILY PRACTICE WALLET ==

The family's first recovery practice should not begin with the main balance after the owner dies.

Create or use a small practice wallet with no meaningful funds. Let the spouse, executor, or trusted helper follow the process-level instructions and recover it under supervision.

The practice teaches the sequence without exposing the main backup or requiring the family to improvise during a crisis.

The main setup can remain private while the family learns what a device, backup, passphrase, account, and provider each do.

== WHERE THIS STATUS COMES FROM ==

A recovery-ready status should mean more than owning a device.

It is based on verified device setup, an offline backup, confirmed receiving and sending, a successful manufacturer-supported backup or recovery test, separated failure domains, and at least one other person understanding the process when the household requires family recovery.

The edit source is the real custody process. Orange Plan records the completion status but does not receive the backup.

And the status affects whether the family can rely on the custody plan, whether the estate process is usable, and whether the Bitcoin allocation has outgrown its protection.

== YOUR DECISION ==

Your decision is the recovery test you are going to perform, the backup locations that survive one physical event, and who else needs to understand the process.
