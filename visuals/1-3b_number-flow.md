# 1.3 · How the numbers flow

## What it has to make obvious
That no number in this app is typed twice. Every figure on screen is calculated from something upstream, has exactly one place it can be edited, and pushes something downstream. It answers the four questions clients asked most: where did this number come from · which page controls it · what changes when I edit it · which account funds this.

## The visual
A single three-band horizontal flow, read left to right, with the bands separated by two large arrows:

    WHAT YOU CHANGE   →   WHAT THE APP CALCULATES   →   WHAT MOVES DOWNSTREAM

Under that master flow, three worked example rows sit stacked, each row aligned to the same three columns so the eye reads them as instances of one pattern rather than three separate diagrams. The column headers stay pinned above.

Each row is visually distinct enough to be recalled on its own later — a module walkthrough will highlight one row and dim the other two.

## Labels and data

Row 1 — the cash-flow chain:

    Income − taxes − living − debt
    → Surplus
    → Reserve funding, contribution routing, retirement date

Row 2 — the life-event chain:

    Life event
    → Future spending in that year
    → Account withdrawals, retirement date, confidence

Row 3 — the assumption chain:

    Return assumption
    → Projected balances and simulated paths
    → Earliest date and confidence number

Column headers, verbatim, because the walkthroughs say these words: **CALCULATED FROM · EDIT SOURCE · THIS AFFECTS.**

⚠ No dollar amounts, no percentages, no dates anywhere in this frame. It is a map of relationships, and any number printed on it would date the graphic and invite a student to read it as their own figure.

⚠ Do not draw the app's actual page chrome. This is the mental model, not a screenshot — the UI moves and this frame should not have to be redrawn when it does.

## Motion
The master three-band flow draws first, left to right, and holds. Then the three example rows build one at a time, each animating along the same left-to-right path so the repetition is the point. End on all three visible together with the column headers pinned.

For per-module recall: fade the frame in complete, then dim to the single row being discussed.
