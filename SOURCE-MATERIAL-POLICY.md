# Source-Material Policy

**Governs:** the uploaded global brain, implementation files, provider notes,
and the custody / inheritance template set.

**Subordinate to:** `AUSTIN-AUTHORITY.md`. Nothing here weakens that rule.

**Established:** Austin, 2026-08-08 — *"don't use those docs as truth, just
rough ideas, they are somewhat old."*

---

## The rule

Uploaded material is **a pool of ideas, not approved curriculum.**

Some of it is conventional, some is rigid, some is provider-specific, and some
is simply not how Austin advises people. Age is unknown and unverifiable, so
none of it can confirm the current state of anything. It can suggest; it can
never verify.

**An old document is not evidence.** If a question is "does the course match the
brain?", the answer comes from reading the brain as it exists today, not from an
upload of unknown vintage.

---

## The four buckets

Everything from a source file sorts into one of these before it can be proposed.

### 1 · Clearly aligned

Reinforces a position Austin has already dictated or demonstrated with clients.
Can be recommended confidently.

Examples already established: known costs need a plan but do not automatically
outrank Bitcoin accumulation · college is a shared funding stack against a
defined parental commitment · allocation is supported by cash flow, debt
capacity, taxes, custody and behavior · custody is not a purity test · document
the process, never the secrets · the family needs a calm starting process, not
technical mastery · every debt gets a deliberate job · current facts, expected
life events and scenarios stay separate · new contributions can fix allocation
mismatches without forcing taxable Bitcoin sales.

### 2 · Requires Austin's approval

Planning judgments. Explain why it may help. **Do not insert.** These become
entries in `AUTHORITY-FLAGS.md`, not course edits.

### 3 · Implementation material, not curriculum

Useful without deserving a lesson. The course teaches *why* and *what to
decide*; a template helps the student execute a decision already made.

Austin still chooses which templates ship. A 15-document toolkit does not get
published merely because the source material contains enough to build one.

### 4 · Keep out of evergreen course

Appropriate for AI assistance, support, or a maintained reference database, but
never recorded on camera:

named lenders, exchanges, hardware wallets and custody companies · current
provider fees, minimums and terms · account-navigation instructions for specific
brokerages · a named will service as the default · current tax limits and
statutory thresholds · current FAFSA and student-loan rules · health-sharing
product terms · specific home-equity products · exchange withdrawal features ·
"this provider is the default" / "avoid this provider" claims · product
recommendations grounded mainly in what Austin personally uses.

The implementation material says this about itself: provider terms must be
freshly verified, and the execution assistant helps implement decisions already
made rather than making the strategic decision.

## Labels for every proposed addition

| Label | Meaning |
|---|---|
| **Add** | Strongly matches dictated philosophy and fills a real gap |
| **Add as template** | Useful for implementation; does not deserve more teaching |
| **Consider** | Potentially valuable, but it is Austin's planning judgment |
| **Already covered** | No need to add; perhaps improve the existing delivery |
| **AI/reference only** | Useful on request, not evergreen curriculum |
| **Do not use** | Conflicts, duplicates, too product-specific, or adds complexity for nothing |

Each proposal states: the exact source idea, where it would go, what student
decision it improves, and why it may or may not fit.

## The standard

Not *"is this information useful?"* but:

> **Does this help the student build, implement, or maintain the Bitcoin
> financial plan, in a way that sounds like Austin?**

## Things not to adopt merely because they appear in a file

Flagged in advance so no future pass imports them silently:

- **A strict traditional contribution waterfall.** Tax benefit, investment menu,
  Bitcoin exposure, liquidity, employer match, and early-retirement access all
  matter. The current lesson can read as though tax-advantaged accounts must be
  fully funded before taxable Bitcoin.
- **Net-worth-driven estate tiers.** A lower-net-worth family with minor
  children, a business, or a blended family can need more planning than a
  higher-net-worth single person.
- **"Bitcoin-aware executor" as a hard requirement.** The course's existing
  position is better: judgment, organization, willingness, and competent
  support. Personal Bitcoin expertise is not required.
- **A named will service as the normal starting point.**
- **Collaborative custody as the default advanced setup.**
- **Every insurance category becoming core.** Identify the risk and route the
  relevant person; do not become an insurance curriculum.
- **Specific self-custody thresholds** (e.g. a fixed exchange balance at which
  to learn self-custody). A personal heuristic is not a universal rule.

## Why this file exists

An assistant presented five old uploaded custody documents as confirmation that
the course's custody levels matched the brain. They confirmed nothing; they were
old drafts. The claim was retracted. This policy exists so the next pass does
not make the same move.
